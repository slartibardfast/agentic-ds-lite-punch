agentic-ds-lite-punch

The carrier environment for end-to-end testing

Status: claimed 11 November 2026, and the active goal. The carrier research, the topology, the carrier's policy plane, the front's deployment, the b4 with its service, the deployment drift check, the harness and the monitors are receipted; the release is cut (v0.6.2) and the lanes carry the attestations. — complete 2026-11-14

What this milestone is

The daemon cannot prove itself without the live line, and the November line-mode change showed what that costs: the rig's fixtures died with the box, the front's relay ran stale against the record once already, and the UDP leg stopped closing mid-flight with nothing able to answer "does the daemon still behave correctly?".

This milestone stands up the environment that fixes the loop for the feature the household actually consumes: the nginx front door. The front is deployed into the environment by the repository's own pipeline (install, render, mint, units), so iterating on the split by name, the relay, the map and the deployment itself is a harness run rather than an edit against production. The carrier around it is a generalised AFTR: the RFC 4787/5382 behavioural space as configuration (mapping and filtering behaviours, timers, port assignment, hairpinning), with carrier profiles as configurations and the measured Virgin Media ds-lite profile as the default instantiation, so the daemon is exercised across carriers instead of against one ISP's idioms. The daemon rides in its b4 namespace, so the whole exchange (poke, admission, forward, answer, push) is exercised with the front in the loop. Every deployment aspect is tested: the files land where the units expect, the certificates are minted the way the line mints them, the deployed files are checked against the record so the stale-relay class of failure fails the harness instead of the household.

The carrier model, the profiles, and the open mapping conflict the harness's differential run settles, are the research.

Deploy the front by its own pipeline

One command deploys the front and probes it from outside the front namespace. mint.sh signs the authority and both identities inside the front namespace, and install.sh renders the configuration and the units with the new --units-dir mode: the namespace has no init to enable them, so the harness starts each unit's own ExecStart line. The distro nginx and its stream module are provisioned unprivileged (apt download and dpkg-deb -x) into the environment's cache, and the pipeline's --nginx and --module name them. The render names the workers' account (user root), because a namespace's setgroups denial makes the package's default account an invalid id and nginx refuses to start over it. For proof, the protected name answers the table over TLS with the daemon's minted identity, and a poke teaches the relay the tuple, which the map records before nginx reloads on it and keeps serving. Nothing is hand-placed.

One command stands the whole exchange up: the carrier's policy plane runs the measured profile, the front is deployed by its pipeline, the echo service answers both protocols beside the daemon, a STUN responder answers in the internet actor, and the real daemon binary dials in with its production flags. The carrier's outbound leg is carried by the policy plane itself, from the carrier's own public tuple: a flow's first packet traverses the postrouting nat chain before its per-flow rule exists, the connection commits as un-natted, and the kernel never translates it afterwards, so the plane delivers what the rule would have and the leak chain keeps dropping what escapes untranslated. The daemon's TLS push rides a lane rule that exists before any flow, opened at policy start toward the poke target, for the same race. For proof: the daemon's writes hold a mapping, a client datagram to the front crosses the slot and the service's answer returns, and the daemon's push reaches the front's report, whose answer names the poke's tuple. The run's log already carries the milestone's differential finding: the daemon's STUN lane and the poke lane hold different external tuples for one source port, which is the open mapping conflict made reproducible.

Check the deployment against the record

  • depends: #front-deployment
  • verify: python3 deploy/env/envctl.py drift-check
  • inputs: software/ds-lite-punch/main/deploy/env/envctl.py, software/ds-lite-punch/main/deploy/front-door/install.sh, software/ds-lite-punch/main/deploy/front-door/render.sh, software/ds-lite-punch/main/deploy/front-door/nginx.conf, software/ds-lite-punch/main/deploy/front-door/poke-listener.py, software/ds-lite-punch/main/deploy/front-door/front-door-nginx.service.in, software/ds-lite-punch/main/deploy/front-door/front-door-poke.service.in

The record the repository ships is what its own pipeline renders now: the check re-runs install.sh into a throwaway root with the deployment's flags and hashes the deployed relay, configuration and units against the probe's, whose bytes are read as if rendered into the deployed root. A deployed tree from an older pipeline passes a snapshot comparison and fails this one, which is the stale-relay class the check exists to catch. For proof, a clean deployment matches the record and a seeded drift (one edited deployed file) fails the check naming its file. The restoration comes from the repository's own installer content, and it matches again.

Assert the whole exchange

  • depends: #b4-and-service, #drift-check
  • verify: python3 deploy/env/envctl.py harness

One command, one carrier profile at a time or all three, asserting the nginx feature end to end: the pass-through name reaches the service's own certificate, the protected name refuses without a client certificate and serves with one, an unpublished name reaches nothing, the datagram leg closes, the relay follows the poke, the push names its view, the lease expires, and the stranger is refused. The rows that depend on the carrier's behaviour assert per profile: the stranger crosses only under endpoint-independent filtering, and the passthrough's egress is the front's own socket, which a port-and-address dependent carrier refuses. Iterating on the nginx feature means editing its source, deploying into the environment, and running this command; the suite runs in the component's CI.

Stand up the monitors

  • depends: #the-harness
  • verify: python3 deploy/env/envctl.py monitors

The repository emits the correlation pair the record calls for. The external monitor watches the published path from outside the line: the protected name's table answer over TLS with the household identity, and the passthrough name's certificate against the service's own. The router-side sampler reads what the line looks like from beside the daemon: its event log since the sampler last looked, the WAN interface's byte counters, and the conntrack weight. Both emit one JSON line per pass in the same shape, so the two streams correlate by timestamp; --once is how the environment's command runs them against the standing exchange, and --interval is the standing cadence on the deployed line. deploy/monitor/README.md documents where each runs and what it takes.

The retired shapes and why

A userspace-only carrier was the first sketch; the operator set the fidelity bar at kernel-real, and the datagram leg's dependence on real nft keying and real decapsulation is what a lighter fake would have hidden. Testing the front only by its harness (the test-local.sh shape) is retired for the same reason: it proves the configuration renders and answers locally, and says nothing about the deployment that puts it on a machine.
