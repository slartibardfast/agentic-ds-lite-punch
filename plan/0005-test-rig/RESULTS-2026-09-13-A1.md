## Design

`sink-stun.py` (binds 0.0.0.0:40002 inside dslp-sink) sends one STUN
Binding Request to an external STUN server that is NOT in the relay's
rotation: stun.nextcloud.com:3478 resolves to <external-stun>, while the
relay rotates stun.l.google.com:19302 and stun.cloudflare.com:3478. A host
route (<external-stun>/32 via 192.168.0.1 dev eth1) forced the request out
via eth1 so it egresses through the pin, the AFTR maps it, and the
response loops back through the same mapping to the sink. The relay must
classify the response source: <external-stun> is not in its rotation, so it
should demux it as DATA and forward it to the sink, which is exactly the
claim under test.

## Observed

- The request egressed eth1 as (<router-eth1-ip>, 40000): the relay's snat
  rewrote the container's 40002 flow into the pin tuple. Evidence, the
  eth1 capture: IP <pin-endpoint> toward <external-stun>:3478, UDP,
  20 bytes.
- The response transited the AFTR mapping to <router-eth1-ip>:40000, was
  received on the relay socket, demuxed as DATA (source outside the
  rotation), and forwarded to dslp-sink.
- sink-stun.py reported XOR-MAPPED-ADDRESS <aftr-tuple>, equal to
  the relay's published tuple: MATCH, exit 0.

## Why this matters

1. The reply leg is end to end proven. The response was an
   external-originated datagram (<external-stun>, a genuinely external
   server) that transited the AFTR mapping and arrived at the sink through
   the relay's forward path. External source to sink, with the relay
   classifying the datagram correctly.
2. The sink's own outbound datagrams share the relay's pin mapping: the
   container's 40002 flow was rewritten to (<router-eth1-ip>, 40000), the
   exact tuple the relay keeps alive, so the AFTR translated it to the
   relay's external tuple. This is the property the echo-on reply path
   (sink-server mode) and the console-through-sink design rely on.
3. The A1 assertion doubles as the external-sourced forward cross-check:
   no Globalping probe is needed, because the STUN response is a real
   third-party datagram delivered through the mapping. A Globalping UDP
   probe would also have been a confound risk during the probe-quiet pause
   campaign, so this completes the check without one.
4. The relay's demux classification is confirmed against a real external
   peer: an address outside the rotation is DATA and forwarded, not
   swallowed as a keepalive response.
